# RealityCheck — Technology and Standards

## Stack

| Layer | Choice |
|---|---|
| Language | Java 21 (compiled with `--release 21`; any JDK 21+ can build) |
| Framework | Spring Boot 3.5.x: Web, Data JPA, Validation, Actuator |
| Database | PostgreSQL 17, Flyway migrations, Hibernate with `ddl-auto=validate` |
| API docs | springdoc-openapi (Swagger UI at `/swagger-ui.html`, spec at `/v3/api-docs`) |
| Build | Maven via the wrapper (`backend/mvnw`) |
| Backend tests | JUnit 5, Mockito, Testcontainers (PostgreSQL), jqwik, ArchUnit |
| Frontend | React + TypeScript + Vite, Tailwind CSS, shadcn/ui, Recharts, React Router, TanStack Query, React Hook Form, Zod, Lucide |
| Frontend tests | Vitest + Testing Library; Playwright for the end-to-end journey (Milestone 8) |
| Runtime | Docker Compose: `db`, `backend`, `frontend` (nginx serving the build and proxying `/api`) |

Exact versions live in `backend/pom.xml` and `frontend/package.json`; do not restate them elsewhere.

### Deliberately not used

Kafka, Redis, Kubernetes, microservices, GraphQL, Lombok, MapStruct, a state-management library beyond
TanStack Query. Spring Security is added only when authentication is introduced. React Flow is added only if
workflows become non-linear. Adding any dependency requires a one-line justification in the commit message.

## Backend coding standards

- Base package `com.realitycheck`. Package by feature, not by layer (see architecture.md).
- Java records for DTOs, value objects and all simulation-engine data. No Lombok.
- Controllers are thin: validate, delegate to a service, map to a DTO. No business logic, no repositories.
- JPA entities never leave the service layer. API types are `*Request` / `*Response` records.
- Constructor injection only. No field injection, no static mutable state.
- Money and quantities are `BigDecimal`; never `double` or `float` for anything persisted or compared.
- Timestamps are `Instant` in Java and `timestamptz` in PostgreSQL. Time zones are applied only at the
  factory-calendar boundary and in the UI.
- Primary keys are UUIDs generated by the application.
- Every schema change is a new Flyway migration `V<n>__<snake_case>.sql`. Applied migrations are never edited.
- Errors use RFC 9457 `application/problem+json` through one `@RestControllerAdvice`. No stack traces or
  exception class names reach the client.
- Secrets come from environment variables only. Nothing secret is logged or sent to the frontend.
- Logging through SLF4J with key=value context (`runId`, `scenarioId`, `factoryId`). Structured JSON console
  output is enabled in the `prod` profile.

### Naming

| Thing | Convention | Example |
|---|---|---|
| Entity | singular noun | `WorkflowStage` |
| Table / column | snake_case, singular table | `workflow_stage.setup_seconds` |
| Repository | `<Entity>Repository` | `ScenarioRepository` |
| Service | `<Feature>Service` | `ScenarioService` |
| Controller | `<Feature>Controller` | `ScenarioController` |
| DTO | `<Thing>Request` / `<Thing>Response` | `CreateScenarioRequest` |
| Enum values | UPPER_SNAKE | `STAGE_COMPLETED` |
| Unit-bearing fields | unit in the name | `setupSeconds`, `hourlyCost`, `stonesPerHour` |
| Test | `<Class>Test`, integration `<Class>IT`, properties `<Class>Properties` | `SimulationEngineProperties` |

## Frontend coding standards

- TypeScript strict mode. No `any`; parse API responses with Zod at the boundary.
- Feature folders under `src/features/<feature>`; shared primitives under `src/components/ui`.
- Server state lives in TanStack Query. No copies of server data in component state.
- Forms use React Hook Form with a Zod resolver; the same schema types the submit payload.
- All API access goes through `src/lib/api.ts`. Components never call `fetch` directly.
- Colours and spacing come from the design tokens in `src/index.css`. No hard-coded hex values in components.
- A value rendered in the UI must come from an API response, or carry a visible "Demo data" label.
- Every data view handles loading, empty and error states.

## Testing expectations

Tests are written with the code they cover, in the same change.

- **Simulation engine:** plain JUnit and jqwik, no Spring context, no database. Every rule in
  simulation-rules.md has at least one test that names it.
- **Services:** unit tests with Mockito for branching logic.
- **Persistence and API:** `*IT` classes against a real PostgreSQL through Testcontainers. No H2.
- **Architecture:** ArchUnit rules keep the engine free of Spring, JPA and AI imports.
- **Frontend:** component tests for forms, validation, and loading/empty/error states.
- **End to end:** one Playwright journey covering the definition-of-success flow.

`./mvnw test` runs unit tests only and needs no Docker. `./mvnw verify` adds the `*IT` tests and needs a
running Docker daemon. A change is not complete until the relevant command passes.

## Commits

Small, single-purpose commits with imperative subjects (`Add resource pool allocation`). A commit that changes
simulation behaviour must bump the algorithm version and say so.

## Client data (spec 11)

Real factory data is read only by local tools, with read-only credentials from `TRYBE_DB_CNF` or another file
outside the repository, and written only outside it (`local/` is ignored). Nothing from it is committed except
the merged, rounded `backend/src/main/resources/demo/calibration.json`, which holds no department, person,
party, lot, packet or order name or identifier. Tests never use real data. Accuracy figures from real
factories are published only as rounded percentages.
